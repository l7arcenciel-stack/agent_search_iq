agent_search_iq — Azureリソース構成

Fabric IQ（オントロジー）を追加した Hosted Agent の環境構築に必要な Azure / Microsoft Fabric / Entra ID リソースの一覧と、最小コストで組む場合の構成案。

作成日 2026-09-20 対象 kojin/01_biz/agent_search_iq ベース azure.yaml / README.md

01全体構成 — 誰の権限で動くか

3つのツール（AI Search・Power BI・Fabric IQ）はそれぞれ別の経路で権限が解決される。ここがこのデモの核心であり、構成ミスが起きやすい箇所でもある。

Path A 文書検索（AI Search） 実行権限 = サインインユーザー本人
サインイン→ OBO トークン交換→ Entra ID グループ→ AI Search（ACLフィルタ）
Path B 構造化データ（Power BI / Fabric） 実行権限 = サインインユーザー本人
サインイン→ OBO トークン交換→ Power BI トークン→ Semantic Model（RLS）
Path C Fabric IQ（オントロジー） 実行権限 = Foundry の呼び出し元
Foundry 呼び出し元→ x-agent-foundry-call-id→ Toolbox (MCP)→ オントロジー
落とし穴： デモUIが Foundry をオペレーターの az login で呼ぶ既定構成だと、Path A/B は本人・Path C だけオペレーター権限になり「誰か」がずれる。FOUNDRY_CALL_AS=user を設定し、サインイン本人のトークンで Foundry を呼ぶ構成にすること。

03セットアップの順序

README 3章の要約。Global Administrator 権限が必要な工程に注意。

  1. セマンティックモデルのストレージモードを確認 — Import の場合はレイクハウス＋Direct Lake化が先に必要結論が変わる分岐点
  2. Fabric管理ポータルで Ontology item (preview) を有効化Fabric管理者
  3. オントロジー作成 → データバインド → リフレッシュ（上流更新は手動リフレッシュが必要）
  4. Fabric IQ 接続用 Entra アプリ登録（委任権限＋管理者同意＋シークレット＋リダイレクトURI）Global Admin
  5. Foundry ポータルで Fabric IQ Connection を作成し接続IDを控える
  6. python setup_toolbox.py を実行し Toolbox の MCP エンドポイントを控える
  7. サインイン用アプリに ai.azure.com 向け委任権限を追加＋管理者同意
  8. 各デモアカウントに Foundry User 相当のロールを付与（無いと403）
  9. 各アカウントで Fabric IQ 接続の OAuth 同意を実施（初回質問時に同意リンクが出る）
  10. azd env new agent-search-iq → azd env list で確認 → azd deploy既存環境と分離必須

04最小コスト構成（個人利用・トライアル優先）

会社経費ではなく個人負担という前提で、まず無料トライアルで賄える範囲を最大化し、トライアル終了後に本当に必要な分だけ課金する構成。米国リスト価格ベースの概算（2026年9月時点、地域・為替により変動）。

前提： Fabricトライアル容量・Power BI個人トライアルは職場または学校（組織）アカウントが必要で、個人のOutlook/Gmailアドレスでは開始できない。既存のEntra IDテナントが無ければ、Microsoft 365 Developer Program（無料E5サンドボックス、開発活動があれば90日ごとに自動更新）でテナントを用意するのが定石。

コストを抑えるポイント

  • まずFabricトライアル容量（60日・無料）でDirect Lake化とオントロジー検証を終わらせてしまう。ここが唯一の重い固定費候補なので、トライアル中に「本当に必要か」を見極める
  • Fabric容量を有償化した後も、デモ前後だけ起動し使い終わったら一時停止する（秒単位課金なので停止すれば$0）。Fabric管理ポータルまたはAzureポータルから操作可能
  • Power BI ProはM365 Developer Program（開発活動があれば自動更新）や個人トライアル60日を使い倒し、有償化は最後の手段にする
  • Azure AI SearchはFree tierのまま運用できないか検討する。SLA無し・長期非アクティブで削除される制約はあるが、個人の検証用途なら許容できることが多い
  • Azureサブスクリプション自体はPay-As-You-Goに切り替えても常時無料サービス（65以上）は残るため、$200クレジットを使い切った後もAI Search Free等は継続できる
  • Foundry / OpenAI 側は完全従量課金なので、検証回数を絞れば固定費は発生しない
